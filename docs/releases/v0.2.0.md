RabbitMA v0.2.0 combines reusable k-iteration work, automatic NUMA placement,
low-memory graph-construction fixes and v0.1.0 output compatibility corrections.
The public command remains `megahit`; existing read, thread, memory, preset and
output options continue to work.

This consolidated publication replaces the earlier v0.2.0 and v0.2.1 releases.
If you downloaded either earlier package, download this rebuilt package and
check its new SHA-256 checksum. `BUILD_INFO.txt` records the exact source commit.

### Download and compatibility

Download **RabbitMA-v0.2.0-linux-x86_64.tar.gz** and its SHA-256 checksum from
the assets below. This is a prebuilt binary package, like v0.1.0.

- Linux x86_64, **glibc 2.17 or newer**, including the CentOS 7 ABI.
- Python **3.6 or newer** available as `python3`, plus gzip and bzip2.
- No compiler, CMake, glibc upgrade or `LD_LIBRARY_PATH` setting is required.
- Includes BMI2/POPCNT, POPCNT-only and portable core binaries, selected at
  runtime, plus the required non-glibc libraries, including `libnuma`.

```bash
wget https://github.com/RabbitBio/RabbitMA/releases/download/v0.2.0/RabbitMA-v0.2.0-linux-x86_64.tar.gz
wget https://github.com/RabbitBio/RabbitMA/releases/download/v0.2.0/RabbitMA-v0.2.0-linux-x86_64.tar.gz.sha256
sha256sum -c RabbitMA-v0.2.0-linux-x86_64.tar.gz.sha256
tar -xzf RabbitMA-v0.2.0-linux-x86_64.tar.gz
cd RabbitMA-v0.2.0-linux-x86_64
./megahit --test -t 4
```

### Changes

- Reuse an exact read-occurrence index across k iterations and fuse the first
  iterative join into index construction, with full-scan fallback when needed.
- Reduce repeated decoding and temporary I/O with packed intermediate contigs
  and reusable read-position information; improve graph construction,
  traversal and local assembly data structures.
- Automatically coordinate concurrent jobs under the same Linux user and
  shared host `/dev/shm`. Jobs that fit within one available NUMA domain reserve
  separate physical-core sets and prefer local memory. Children retain the
  reservation until they exit.
- Respect scheduler CPU/memory allowances, explicit affinity and memory policy,
  SMT topology and cgroup v1/v2 memory limits. Fractional `-m` budgets follow
  the reserved NUMA CPU share; local memory can fall back to remote memory.
- Fix streamed graph construction under small memory budgets. The safety reserve
  scales below 2 GiB, and budgets that cannot support direct-record bookkeeping
  use resident edges and valid compact locators. Existing large-budget behavior
  is retained.
- Restore v0.1.0 finite-window semantics for circular `k*.addi.fa` evidence,
  avoiding added or removed sequence windows at a circular cut. Both FASTA and
  packed intermediates follow the same rule.
- Restore reference path ownership, stored strand and linear-merge priority
  from endpoints and lengths, including after initial tip removal. Graph walks
  remain parallel; worker lock-arrival order no longer selects merge ownership.

For example, on two NUMA domains with 36 available physical cores each:

```bash
./megahit --12 sample_A.fq.gz -t 36 -o sample_A.out &
./megahit --12 sample_B.fq.gz -t 36 -o sample_B.out &
wait
```

When CPU and memory allowances permit, the jobs reserve different domains
without extra environment variables or `numactl`. Three 16-thread jobs on two
32-core domains also receive disjoint CPU sets: two jobs share one domain and
one occupies the other. Jobs in the same domain still share memory bandwidth.

The log reports `Automatic NUMA placement` and the reserved CPU IDs. Absolute
memory budgets must fit each job's NUMA CPU share. If placement cannot be
applied, the default mode keeps inherited placement. In particular, three
24-thread jobs cannot all fit within individual domains on a two-by-36-core
machine: the third falls back instead of reserving 12 cores from each domain.
Use `--numa-node off` to disable automatic placement.

### Output reference and validation

The fixed reference for circular intermediate evidence is the published
v0.1.0 single-worker builder. Old multi-threaded executions can themselves
choose different circular origins and produce different later assemblies;
this release does not promise equality with every such old execution.
Comparisons retain sequence orientation, circular cut, k, flags and stored
coverage, excluding only record IDs and order.

The source audit passed 95 tests on each of the three CPU variants (285 tests).
On a CAMI3 subset of 2,000,000 read pairs, all 60 final/intermediate files
matched the complete published v0.1.0 single-thread pipeline. Two concurrent
new 32-thread runs matched each other, and full CAMI3 sample_0 runs at 32 and
64 threads matched in all 60 files. The full sample was not run through the
entire old single-thread pipeline; direct old single-thread checks covered
its k109 graph. See the
[compatibility notes](https://github.com/RabbitBio/RabbitMA/blob/v0.2.0/docs/compatibility-v0.1.0.md)
for the remaining checks and reference limitations.

The portable release workflow runs the full regression suite on all three
packaged cores, audits ELF dependencies against glibc 2.17 and tests both
normal and portable dispatch in a 1 GiB glibc 2.17 container before publishing.

An earlier controlled dual-NUMA CAMI3 experiment measured **1.84x node
throughput** for two concurrent 32-thread jobs. That experiment isolates
resource placement and memory budgets on the then-validated core; it predates
these output-compatibility corrections and is not a new speed measurement of
this consolidated package. See
[BENCHMARKS.md](https://github.com/RabbitBio/RabbitMA/blob/v0.2.0/BENCHMARKS.md).
Experimental `MEGAHIT_EXPERIMENTAL_*` paths remain opt-in.
