RabbitMA v0.2.0 adds reusable work across k iterations and automatic NUMA
placement for concurrent assembly jobs. The public command remains `megahit`;
existing read, thread, memory and output options continue to work.

### Download and compatibility

Download **RabbitMA-v0.2.0-linux-x86_64.tar.gz** and its SHA-256 checksum from
the assets below. This is a prebuilt binary package, like v0.1.0.

- Linux x86_64, **glibc 2.17 or newer**, including CentOS 7.
- Python **3.6 or newer** available as `python3`, plus gzip and bzip2.
- No compiler, CMake, glibc upgrade or `LD_LIBRARY_PATH` setting is required.
- Includes BMI2/POPCNT, POPCNT-only and portable core binaries, selected at
  runtime, plus the required non-glibc libraries, including `libnuma`.

```bash
wget https://github.com/RabbitBio/RabbitMA/releases/download/v0.2.0/RabbitMA-v0.2.0-linux-x86_64.tar.gz
wget https://github.com/RabbitBio/RabbitMA/releases/download/v0.2.0/RabbitMA-v0.2.0-linux-x86_64.tar.gz.sha256
sha256sum -c RabbitMA-v0.2.0-linux-x86_64.tar.gz.sha256
tar -xzf RabbitMA-v0.2.0-linux-x86_64.tar.gz
cd RabbitMA-v0.2.0-linux-x86_64
./megahit --test -t 4
```

### Changes

- Reuse an exact read-occurrence index across k iterations and fuse the first
  iterative join into index construction, with full-scan fallback when needed.
- Reduce repeated decoding and temporary I/O with packed intermediate contigs
  and reusable read-position information; improve graph construction,
  traversal and local assembly data structures.
- Automatically coordinate concurrent jobs under the same Linux user and
  shared host `/dev/shm`. Each job that fits in one available NUMA domain
  reserves physical cores and prefers local memory. Child processes retain
  reservations until they exit.
- Respect scheduler CPU/memory allowances, existing explicit affinity and
  memory policy, SMT topology, and cgroup v1/v2 memory limits. Fractional `-m`
  budgets follow the reserved NUMA CPU share. Local-preferred allocation can
  fall back to remote memory under pressure.
- Preserve circular-contig flags independently of thread count.

For example, on two NUMA domains with 36 available physical cores each:

```bash
./megahit --12 sample_A.fq.gz -t 36 -o sample_A.out &
./megahit --12 sample_B.fq.gz -t 36 -o sample_B.out &
wait
```

With both domains available, the jobs reserve different domains without extra
environment variables or `numactl`. The log reports `Automatic NUMA placement`.
Existing scheduler restrictions still apply. When placement cannot be applied,
the default mode keeps inherited placement. Use `--numa-node off` to disable it.

### Validation and performance scope

The synchronized computation core passed 87 regression tests on each of the
three CPU variants (261 runs), plus StreamStore boundary/byte checks and local
minimizer witness checks. Eight complete toy pipelines and full merged CAMI3
k39 assembly comparisons passed 142 exact output checks, retaining sequence
orientation, k, flags and coverage while ignoring record IDs and order.

In the measured dual-NUMA CAMI3 experiment, two concurrent 32-thread jobs
completed in 2354.42 seconds instead of 4324.07 seconds: **1.84× node throughput**.
That comparison isolates the launcher resource policy on the same validated
computation core, and includes CPU placement and memory-budget changes. It is
not a universal speedup over v0.1.0 or a promise for a single exclusive job.
See [BENCHMARKS.md](https://github.com/RabbitBio/RabbitMA/blob/v0.2.0/BENCHMARKS.md)
for measurement scope.

Experimental `MEGAHIT_EXPERIMENTAL_*` paths remain opt-in. The rejected NUMA
graph-replication and native/LTO experiments are not enabled in this release.
